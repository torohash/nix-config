# Semantic Generation

共通指示の `referent-before-label` rule に従い、語を選ぶ前に指示対象と役割を固定する。対象文書の本文は、先に独立保存した referent table の写しとして生成する。

## 適用を判定する

次のいずれかに当てはまる場合に使う。迷ったら適用する。

1. 設計資料、要求からの設計、調査報告、原因切り分け案、対策案を書く。
2. 公開仕様、状態名、条件名、事象名、値または記録の型名、メソッド名、boolean 名を命名する。
3. ユーザーの推論順序を短い作業ラベルへ要約する。

引用、単純な機械編集、既存名の再利用、定型出力、雑談、確立した用語だけで書ける短文には適用しない。

## 対応表を先に独立提出する

1. 本文を1文字も書く前に、出典から指示対象、役割、前後関係を抽出する。
2. 作業ディレクトリの `referent-table-<slug>.md` へ対応表を独立成果物として保存する。完成成果物を `output/` 配下へ置く場合は、その成果物と同じディレクトリへ保存する。
3. 次の列を正確な順序で使う。

   | 出典 | 目的 | 具体対象 | 役割 | 前後関係 | 候補語 | 初出定義 |
   |---|---|---|---|---|---|---|

4. `shasum -a 256 <path>` などで保存済み対応表の sha256 を計算する。対応表の保存先と sha256 を記録してユーザーへ提出してから本文工程へ進む。

完成文書の先頭へ対応表を置くだけでは、独立提出として扱わない。

## 対応表を設計する

- 1行は、一つの具体対象と一つの役割の対応を表す。
- `候補語` は右端側に固定し、`具体対象` と `役割` を確定するまで空欄にする。
- `役割` は `開始条件 / 状態 / 事象 / 値 / 記録 / 目的 / 手段` から一つだけ選ぶ。同じ語が複数の役割を持つ場合は行を分ける。
- `前後関係` はユーザー原文の推論順序を保つ。
- 通常は1〜6行に収める。7行以上になる場合は、意味境界ごとに表を分ける。
- `候補語` を隠しても、`具体対象` だけで指示対象の意味が通ることを確認する。
- `候補語` はユーザー用語、次に確立した用語を優先する。新語を導入するときは `初出定義` に「X とは〜を指す」と書く。既存語では `ユーザー用語` または `確立用語` と記録する。初出定義を書けない語は導入しない。

## 対応表から本文を生成する

- 本文を対応表の写しとして書き、中心語彙には対応表の `候補語` に載せた語だけを使う。
- 日本語文、設計要素、コード識別子の三層で、具体対象と役割の対応を保つ。
- 開始条件、事象、状態など、異なる役割には異なる名前を付ける。
- 目的、対象、判断を示せない抽象的な作業ラベルを、本文の骨組み、見出し、結論に使わない。

## 問題を修正する

- 対応表なしで本文を書き始めた場合は、その本文を破棄し、対応表から再生成する。
- 対応表の指示対象または役割の誤りを指摘された場合は、該当行を直し、本文の該当箇所を再生成する。
- Skill を読めない環境でも、最低6列の `出典 | 目的 | 具体対象 | 役割 | 前後関係 | 候補語` を持つ表を独立保存してから本文へ着手する。

この Skill の本文へ検証用の試験入力や期待回答を追加しない。必要な fixture は別に管理する。誤用語リストとの照合を目的にせず、生成順そのものを制御する。
